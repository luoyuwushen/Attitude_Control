## 官方附带工具核验

输入：桌面 `接口驱动参考案例测试工具.exe`。SHA256：`08212c00c65944166db22e6afe705a3c968e7f3420ccade2bb99dca90cdec353`。

通过 PyInstaller archive 中 `serial1.py` 的静态字节码核验，工具提供串口选择、波特率选择、三个十进制原始读数及接收十六进制日志；解析固定 10 字节：`AA 55`、三个大端 unsigned16、`0D 0A`。未找到串口写入调用、CRC、序号、物理单位换算、曲线或 CSV 采集。

本地官方 `Interface_test/src/top.v` 将 ADC 滤波计数及两个编码器原始计数交给 `uart.v`。ADC 字段不是角度单位，编码器起始值 10000 不是实际机械零位。`uart.v` 在不同字节发送时更新输入寄存器，不能将它当成一致采样快照。

当前项目/FPGA v1 协议采用 115200/8N1、24 字节小端帧、signed Q10 角度与速度、CRC16 和序号。两套协议不兼容，改变波特率不能解决解析差异。host-v0.3.0 上位机可在独立通用模式查看官方格式的原始 HEX/文本，不将官方三原始数值强行换算成姿态，也不将通用数据用于项目辨识。

## 本项目选取的功能

1. 保持现有 v1 FPGA 遥测与 ASCII 命令，避免修改控制链路才能使用上位机。
2. 实时绘制 ADC、摆杆角度与估计角速度、摆臂角度与估计角速度、PWM 请求指令，同时显示状态、标定和控制器故障。
3. 以独立会话保存 CSV、通过校验的原始帧、人工事件、现场条件和指标摘要；明确串口、演示与回放来源。
4. 显示 CRC、序号缺口、重复与重启诊断；连续保持与捕获计时遇缺口、超时或异常时中断。
5. 为设备时间、原始编码器计数、目标位置/速度、观测角度/置信度、能量误差及参数版本预留 v2 TLV 接口。当前固件未上报的量不填零，不开放不存在的参数写入功能。
6. host-v0.3.0 支持可保存的自定义波特率及完整串口格式设置；项目控制仅允许 project-v0.1.1 FPGA 的 115200/8N1，通用收发按独立模式运行且不自动发停止字节。
7. ADC 静态段、机械参考 CPR、疑似盲区扫描、自由衰减、点动/滑行与机械人工记录统一放在手动开启的开发者二级窗口，保存来源、参数及证据 CSV；启动不自动进入，日常页面保留遥测与运行。

## 测量边界

- 控制周期为 1 kHz，UART 遥测约 50 Hz；实时图表和指标是遥测采样结果，不能恢复每个控制周期的峰值。115200/8N1 的线速也不支持以 24 字节帧直接上报完整 1 kHz 数据。
- 停机时两个速度估计清零，不能以它们判断手动机构已经停止。使用 ADC、角度和位置变化核验手动方向。
- 当前遥测未直接提供原始累计计数。已知本次固件系数、同一原点、未饱和且映射可逆时，可从完整 Q10 角度逆算相对计数后进行独立机械单圈测量（条件见本地用户手册）；不能将“角度显示360°”直接作为 CPR 验证。绝对累计计数仍需后续固件上报。
- 小角度自由衰减分析要求固定摆臂、下垂 ±15° 范围和可信连续峰值，只估计归一化 `b/J`、`mgd/J`；绝对质量、惯量与阻尼不能凭当前遥测自动得出。尺寸、质量与质心由人工测量记录，未知保持空白。
- ADC 扫描只定位疑似跳变和近电压轨采样点，不能独立测得盲区机械角度；点动分析以主机时间和位置变化估计时长、位移和速度，不等于实测电机力矩或精密时间常数。
- `command` 是请求控制量，不是实测力矩、电流或最终 PWM 输出；套件没有新增温度、电流测量接口。
- project-v0.1.2 及之后补充板级聚合故障和启动诊断，host-v0.5.0 直接解释；`fault=0` 仍不保证当前状态、停止键和标定均允许启动。命令没有 ACK，写入串口与设备执行须分别判断。

具体使用方法见 [上位机 README](../host/README.md)，字节协议与后续升级接口见 [PROTOCOL](../host/PROTOCOL.md)。

## 本轮闭环集成核查（2026-09-27）

两个新增参考仓库的 README 已联网核验。采用的边界是 FPGA 负责实时反馈和 PWM，上位机负责请求、状态解释、故障及运行记录；界面交付和磁盘保存有界，不能反向阻塞硬件控制。自动运行日志与可选原始字节日志、实验 CSV 分开保存，保留来源与异常。

XH1 驱动对应 TB6612 B 桥的结论来自本地 `Balance_Ctrl_20260618.pdf` 第 1 页电路、第 2 页 PCB 连通分组及用户手册 PDF 第 26～27 页，不来自 GitHub 示例。旧版只驱动 A 桥却采集 XH1 编码器，属于板级绑定错误。官方 Interface_test 同时驱动两桥和读取两编码器，其电机转动现象不能区分单桥映射。

## 用户指定同届工程的适配复核

核查固定提交 `a65f4c3f4750df0ef953c66e38a4afe55a5de3e1`，避免后续 main 变化混淆依据。该项目的 [硬件顶层](https://github.com/pjj644/gowin-furuta-pendulum/blob/a65f4c3f4750df0ef953c66e38a4afe55a5de3e1/furuta_lqr_ctrl/src/j280_hw_top.v) 使用 12 位 SPI 角度输入，当前 J280 为 10 位并行 3PA1030；顶层没有 UART/上位机接口，不能直接解决本项目启动反馈和日志需求。

其 [CST](https://github.com/pjj644/gowin-furuta-pendulum/blob/a65f4c3f4750df0ef953c66e38a4afe55a5de3e1/furuta_lqr_ctrl/src/furuta_lqr_ctrl.cst) 将电机 PWM/DIR 配到 H19/H18、IN1/IN2 配到 G17/G18、STBY 配到 F18；这些球位在本地官方原理图分别涉及 ADC 数据、ADC 时钟及 OTR。它把 SW2 描述为 R2 停机刹车开关，而本板 SW2 为 R18 的低有效按键。其编码器假设为 4000 CPR，与本项目待实测的 1040 标称推导也不同。**不复制其管脚、单点标定、反馈增益或故障自动再起摆策略。**

可比较的算法思路包括 [状态机](https://github.com/pjj644/gowin-furuta-pendulum/blob/a65f4c3f4750df0ef953c66e38a4afe55a5de3e1/furuta_lqr_ctrl/src/ctrl_fsm.v) 的初始激励保持、[起摆控制](https://github.com/pjj644/gowin-furuta-pendulum/blob/a65f4c3f4750df0ef953c66e38a4afe55a5de3e1/furuta_lqr_ctrl/src/swing_up_ctrl.v) 的能量项，以及硬件顶层的平衡位置刚度渐入；本项目已有对应算法，调整前须用实测参数比较。其 [动力学模型](https://github.com/pjj644/gowin-furuta-pendulum/blob/a65f4c3f4750df0ef953c66e38a4afe55a5de3e1/furuta_lqr_ctrl/src/furuta_plant_model.v) 将姿态映射回传感器码并通过引脚回注，适合作为完善端口级闭环验证的思路，仿真结果不替代 J280 实物验收。

其状态机在跌落后自动再起摆、软限位解除后可再次启动，本项目保留显式启动与故障处理；编码器清零不能证明绕线已解除。该顶层只有曾经采样标志，未见对应的采样新鲜度看门狗，不能替代本地 2 ms 保护。其标作 HIL 的行为模型闭环仍属仿真，不作为本项目实板证据，也不以增加初始激励来修复错误的电机端口绑定。
