# H 逐周期实测与接管确认

2026-09-28。v0.2.9 的首份连续记录验证了数字控制链，但仍有约 2.5 秒的摆臂往返和约 11 Hz 的快速输出变化。另一次 H 请求被拒收，说明“点击按钮”和“FPGA 已进入平衡”需要明确区分。现有证据不支持把两者统一归因于启动力度不足。

## 连续记录给出的事实

21:59:57 会话关联导出 `20260928_140108_638596_2757901f`；导出目录使用 UTC，普通会话目录使用本地时间。固件为 `0x00020009`，588 个历史包全部 CRC 正确，4096 行样本计数 63148～67243 连续。它保留本次 16463 个 H 提交中的最后 4096 行，约 4.096 秒；不能把它说成完整的 16 秒逐周期记录。

用户确认本次按 H 后立即松手、全程未接触，最后主动 S。H 可见区间约 16.46 秒；冻结原因是停止，首次 ADC 故障在冻结后 541 ms，不能作为 H 退出原因。

| 检查 | 结果 |
| --- | --- |
| 同次实时遥测 | 3059 帧 CRC 正确、序号连续 |
| ADC 映射、编码器原点、反馈命令、方向映射 | 4096 行逐整数一致 |
| 两路速度滤波、积分、控制年龄递推 | 4095 个连续间隔全部一致 |

| 连续记录中的故障、满输出、积分触界 | 均为 0 |

| 连续窗口积分 | 约 6.18‰～18.12‰ |

每毫秒编码器变化只有 −1、0、+1，分别为 608、3059、428 次；ADC 均值每毫秒变化在 −13～+16 Q4，即不足或等于一个整数 ADC 码。单步请求变化为 −82‰～+89‰。按各项变化绝对值最大者分类，2655 次来自摆臂速度项、1437 次来自摆杆速度项、3 次来自摆杆角度项。这说明差分估速及反馈如何传播变化，不证明输入变化是噪声。

1 kHz 数字记录中约 11 Hz 的分量仍存在，已不能仅用 50 Hz 上位机抽样混叠解释。它集中在慢往返的部分阶段，两个速度反馈项同频叠加。现有传感器没有独立机械真值，不能据此确定是机械振动、传感器干扰或闭环相互作用。

## 启动温和与未接管分别判断

上述成功会话的前约 0.384 秒，50 Hz 抽样请求在 −83‰～−1‰，确实较温和。当前位置反馈分四档加入，但摆杆角度、摆杆速度、摆臂速度反馈从接管时就生效。小角度、低速度下小输出符合现行公式，不等于板上 PWM 没有执行，也不代表有充分捕获余量。这里没有官方 PID 的原始输出记录，不能比较两者的精确增益或实际力矩。

## 当前处理

上位机接管提示必须以新鲜设备状态为依据，明确区分发送中、尚未接管和 H 已运行。`已写入 H`、历史锁存的“启动已接纳”均不能作为此次接管完成的证据。等待确认期间不自动重复 H；停止仍立即优先，原接管范围及保护不放宽。

现场顺序为：扶稳近直立，点击 H，确认当前状态已显示直立平衡，再松手。若仍待机或提示未接管，保持停止并查看原因；不要松手后用重复点击追赶下落的摆杆。运行中先扶住多久、实际松手时刻应与连续记录一起保留，便于区分捕获能力和稳态控制表现。

周期晃动尚未修复。继续增大速度反馈、强制最小 PWM 或放宽 ADC/位置保护都缺少足够依据。角度差分增加小数位可改善量化，但保持原带宽的回放并未明显减少快速分量：舍弃前250ms假定滤波初态后，请求差异RMS为2.79‰，8～30Hz带内RMS约82.37‰，变更前后几乎一致。固定轨迹回放不能证明修改后闭环会稳定，也不能单独排除模拟传感器问题。见[反事实回放](../Release/reports/h_20260928_trace_audit/candidate_replay.json)。

## 离线分析与证据

`tools/analyze_control_trace.py` 从原始包重新校验 CRC 并恢复数据，仅对明确的 v0.2.9 默认参数复算。分别输出传输完整性、采样连续性、数字一致性及反馈分项，不信任归档里的派生角度字段。未知固件不推测增益，断号不插值，首行速度取记录值而非人为清零。

维护者可对已导出的文件运行以下只读分析；输出必须是新目录，不覆盖原件：

```powershell
python tools/analyze_control_trace.py <capture.json路径> --output <新分析目录>
```

专项测试覆盖真实 RTL 串流 290 行、正负取整、积分边界、样本回绕/缺口、篡改和已知频谱。频谱仅使用最长连续健康段；4 秒左右的窗口不足以单独证明 2.5 秒慢周期已经收敛。
