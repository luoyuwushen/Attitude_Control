# 静止采样故障与绘图积压修复

适用：project-v0.2.1 / host-v0.6.1。官方 PID 在同一硬件、接线和传感器位置下能松手平衡是用户确认的对照；本版实际起摆和平衡仍待实物验证。前版研究与三篇资料的访问情况见[ADC 重构与官方 PID 对照](ADC重构与官方PID对照.md)。

## 已核对的现场现象

用户确认：自然下垂、保持静止，SW5 复位瞬间故障为0，随后重新出现0x01；电机没有启动。“保持待机”在本文只指控制器不输出驱动，不是要求把已经转动的电机停下来。

- 21:51～21:55的四会话共9950帧，固件实际自报0x00020000，全程待机、门控后命令为0。勾选两项操作确认后，G/H/F/B仍因sensor_fault锁存禁用，未发送运动命令。
- 21:53:37会话D224/U759标定后，seq550、设备11020ms故障曾清0，seq551、11040ms重新锁01；整个会话没有OTR，131个可见坏窗的原码跨度均超过32。50Hz遥测不能确定这20ms中哪个1ms窗口最初触发，不能把seq551当下的正常窗口说成故障窗口。
- 22:04会话包含三次复位，分别在约200、100、60ms内重新锁01；当时尚未标定，没有当前OTR或接口锁存。22:05自然下垂静态片段均值约220，仍能看到204～251等原码极值窗口。
- 21:51会话seq14250→14251在20ms间由原码0变成1023，并有OTR。机械位置和顺时针方向来自用户描述，日志不能独立证明传感器机械盲区或ADC数字逻辑错误；它与静止时无OTR重锁是两个需要区分的现象。
- 22:38、22:39重新连接后的首帧均已sensor_fault=1；设备时间2018240→2079740ms连续增加，未标定、驱动0。重连显示既有锁存，不等于上位机下发了启动或故障命令；这些记录本身不排除USB连接对模拟电路的其他影响。

## 采样链的直接缺陷与改动

v0.2.0每毫秒从约5000个5MHz原码中取极值，只要跨度超过32，即把该窗口标坏。估算器在未标定状态也将一次坏窗永久锁为sensor_fault；D/U只是当拍可能清除，后续坏窗又重锁，R不触及传感器锁存。这解释了复位短暂清0、静止很快重报以及勾选无法开放按钮的代码路径。

原码极值跨度不是16点平均测量误差，现有日志也没有记录每个微秒级样本，不能预先断言所有异常都是单点毛刺。本版区分原始证据、滤后可信度和锁存恢复：

1. 连续原码经过两级寄存的三点中值后，再参与原16点、1ms平均。孤立非轨端尖峰可以剔除，滤波不改变采样相位或控制增益。
2. 所有原码的OTR与0/1023轨端旁路滤波并整窗保留。原码min/max继续上报，原码跨度超过32仅作警示。
3. 全5MHz滤后流及16个实际贡献样本的联合窗口跨度超过32、相邻中值步进超过32、滤波未填满仍判坏；估算器的相邻均值跳变、角度映射与采样超时保护保持。包含滤后整窗极值，是为了拒绝完整发生在两个贡献采样之间的平滑异常脉冲，不能只检查离散贡献点。
4. 持续异常仍会停止并锁存。只有停机、当前采样新鲜且合格、连续16个好窗口之后，显式R才能清传感器锁存；已经标定时还要求估计有效和就绪。清除保留D/U，不会自动启动；持续坏窗、断采或运行中不能靠R解除。
5. 新增质量原因、首次传感器故障原因及触发窗口极值/均值，保留已被50Hz遥测漏掉的1ms异常证据。v2扩为106字节，原字段位置与旧v1/v2解析保持兼容。

不采用简单扩大32码阈值、忽略OTR、反复自动清故障、强制放开按钮或增大PWM的方法。本版中值对连续异常、持续偏差仍可能拒收；实板是否恢复稳定，必须看新记录。输入异常来自模拟噪声、接触问题还是数字捕获裕量，现有证据尚不足唯一定位。

## 串口卡顿的独立原因

前两会话确有交付队列溢出并断开，分别有64、69字节未交付；记录处理延迟最高约14.931、10.589秒。因此已保存帧CRC正确不能证明整条接收链稳定。

离线重放使用实际旧版遥测，通过正常worker排队、Qt交付、界面处理及异步日志，未打开COM。无分析器对照的500帧片段中，原版绘制均约34.898ms，加状态更新约4.682ms，已接近40ms刷新周期；单像素、无抗锯齿后绘制均约14.922ms。原始串口面板flush约0.425ms，未复现旧版缓存填满的全量重排为本次主因。

host-v0.6.1将曲线绘制独立为10Hz，采用单像素线；无新数据、曲线隐藏或冻结时不重绘。接收、逐帧日志和控制条件保持原节拍，不通过丢帧或扩大交付队列掩盖负载。

最终离线验收预填300秒显示历史，在1366像素窗口下连续重放90.062秒，发布、接收、日志均为4500帧且原始内容一致，积压溢出0；交付延迟p99为47ms、最大62ms。89次停止按钮回调最大延迟32ms，不代表串口发送或电机停止延迟。重放依据旧记录重建完整帧批次，原始串口字节分片不可得。209项Python、15组RTL及50MHz构建通过，Fmax54.191MHz；详细证据见[本版验证](project-v0.2.1_validation.json)。这些结果不能代替物理串口长时验收。

## 下一次实物操作

### v0.2.1后续实测补充（23:19～23:26）

R恢复及正反点动已经实测可用，但自动起摆仍未通过：三次G被接纳后触发0x01，传感器首因分别0x2c、0x24、0x24，均为滤后窗口跨度异常，其中一次另有相邻中值突变；首因未包含OTR、轨端或相邻窗口均值突变。当前极值与均值不足以还原异常持续时间，三点中值不能认定已解决现场干扰。后续需要首异常时刻、滤后范围、转换超限数量/持续长度及PWM关联，不能只扩大阈值或增加驱动力。点动还显示命令到编码器的符号与当前模型相反，需要与摆杆耦合坐标共同核验。此结论与此前离线通过并存，不将其写成实板起摆已完成。

### 新下载后的首次观察

先下载本版位流并打开配套上位机，确认设备实际显示project-v0.2.1。保持自然下垂、静止观察30秒，暂不标定或启动，用于核对复位后自发0x01是否重现；不需要反复按停止、清故障或复位。如果仍异常，保留“锁存传感器原因”和“触发时原码窗口”，不要自动试点动。

静态采样持续正常后再D/U，并沿已知连续路径缓慢往返核验；此前发现0→1023的路径仍未验证可用。完成采样与实际方向、范围核验后再试H直立接管，最后验证G/SW2自动起摆。两点标定、勾选确认、清除故障都不能替代这些实物验收。
